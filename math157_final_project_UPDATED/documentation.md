# Math 157 Final Project Documentation

## Formalizing the Sum of the First `n` Odd Numbers in Lean

For my Math 157 final project, I formalized the theorem that the sum of the first `n` odd numbers is `n^2`. The theorem states that the sum of the first n odd numbers is equal to `n^2`. For example, `1 + 3 + 5 + 7 = 16`, and `16 = 4^2`.

For example, when `n = 4`, the sum is `1 + 3 + 5 + 7 = 16`, and `16 = 4^2`. This is a familiar theorem from algebra, but it's a good formalization project because it shows how even a simple proof needs to be written very carefully when a proof assistant checks every step. My code uses Lean and Mathlib to define the odd number sequence, define the finite sum of the first `n` odd numbers, and prove the main theorem by induction.

My learning goal for this project was to understand how an informal induction proof becomes a formal proof in Lean. In a regular written proof, I could say, “By the induction hypothesis, the sum is `n^2`, so adding the next odd number gives `n^2 + 2n + 1 = (n + 1)^2`.” In Lean, that same reasoning has to be represented through definitions, rewriting, and tactics. This helped me practice the difference between knowing why a theorem is true and writing the proof in a form that a computer can verify. I also wanted to practice making a Lean file readable to another person, not just making it compile.

I'm currently taking Math 109, I've practiced writing proofs, especially proof by induction. That helped because the mathematical proof of this theorem is based on induction. In Math 157, I've learned how Lean uses definitions, theorem statements, tactics, and imported Mathlib lemmas to check mathematical arguments. Earlier assignments also introduced me to `Finset`, finite sums, and the idea of breaking a proof into smaller parts. I used that background to make this project self contained and realistic for my level.

The code component begins by defining the `n`th odd number as `oddTerm n := 2 * n + 1`. This indexing starts at `0`, so `oddTerm 0 = 1`, `oddTerm 1 = 3`, `oddTerm 2 = 5`, and so on. Then I define `sumOddTerms n` as the sum of `oddTerm i` over `Finset.range n`. Since `Finset.range n` contains the numbers from `0` through `n - 1`, this represents the first `n` odd numbers. I included several small examples showing that the definitions give the expected values for the first few cases. These examples are not the main theorem, but they help make the code easier to read and check.

The main proof uses induction on `n`. The base case is `n = 0`, where the sum over an empty range is `0`, and `0^2 = 0`. In the inductive step, Lean assumes the theorem is true for `n`; this is the induction hypothesis. Then the proof uses `Finset.sum_range_succ` to rewrite the sum of the first `n + 1` terms as the sum of the first `n` terms plus the next term. After applying the induction hypothesis, the goal becomes the algebraic identity `n^2 + (2n + 1) = (n + 1)^2`. Lean finishes this with the `ring` tactic.

One important update I made from the earlier draft is that the final theorem no longer contains sorry. In the earlier version, the structure of the proof was present, but the induction step was unfinished. For the final version, I completed the proof and added a helper lemma called sumOddTerms_succ, which makes the induction argument easier to follow. Breaking the proof into smaller pieces made the code more organized and easier to understand. I also included comments throughout the Lean file so that the purpose of each definition and theorem is clear to someone reading the code.

The hardest part of the project was translating a simple human proof into the exact form Lean needed. The mathematical idea is short, but Lean requires the statement to be written precisely. For example, the usual informal statement uses `1 + 3 + ... + (2n - 1)`, but Lean needs an exact finite set of indices. I chose `Finset.range n` because it naturally represents the first `n` terms. Another challenge was the induction step. In a written proof, the step from `n^2 + 2n + 1` to `(n + 1)^2` feels automatic. In Lean, I needed to unfold the definition of the odd term and then use an algebra tactic to verify the equality.

The scope of this project is appropriate because it's not trying to formalize a large or advanced theorem, but it still requires real Lean work. The project uses definitions, examples, a helper lemma, induction, finite sums, and algebraic simplification. It's original in the sense that I chose the theorem, organized the Lean file, wrote the explanatory comments, and connected the formal proof to my own learning in the course. It's also relevant to Math 157 because the entire project is about formalizing a mathematical proof in Lean.
